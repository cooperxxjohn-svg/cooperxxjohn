# Revert last migration
alembic downgrade -1

## 📝 Creating New Migrations

### When to Create a Migration

Create a new migration when you:
- Add a new model/table
- Add/remove columns
- Change column types
- Add/remove indexes
- Add/remove constraints
- Change relationships

### Step-by-Step Process

#### 1. Update Models

Edit `models.py` with your changes:

```python
# Example: Adding a new column to User model
class User(Base):
    __tablename__ = 'users'
    
    # ... existing columns ...
    
    # New column
    phone_number = Column(String(20))  # Add this
```

#### 2. Generate Migration

```bash
alembic revision --autogenerate -m "Add phone number to User"
```

This creates a new file in `alembic/versions/` like:
`abc123def456_add_phone_number_to_user.py`

#### 3. Review Migration

**ALWAYS** review the generated migration file:

```python
def upgrade() -> None:
    # ### commands auto generated by Alembic - please adjust! ###
    op.add_column('users', sa.Column('phone_number', sa.String(length=20), nullable=True))
    # ### end Alembic commands ###
```

**Common Issues to Check:**
- Nullable vs NOT NULL (especially for existing data)
- Default values for new columns
- Index names (can be too long)
- Foreign key constraints

#### 4. Apply Migration

```bash
alembic upgrade head
```

#### 5. Test

```bash
python test_database.py
```

## 🔄 Migration Workflow

### Development Flow

```bash
# 1. Make changes to models.py
vim models.py

# 2. Generate migration
alembic revision --autogenerate -m "Descriptive message"

# 3. Review the generated migration file
cat alembic/versions/XXXXX_descriptive_message.py

# 4. Edit if needed (add data migrations, fix issues)
vim alembic/versions/XXXXX_descriptive_message.py

# 5. Apply migration
alembic upgrade head

# 6. Test
python test_database.py

# 7. Commit migration file
git add alembic/versions/XXXXX_descriptive_message.py
git commit -m "Add migration: descriptive message"
```

### Production Deployment Flow

```bash
# 1. Pull latest code
git pull origin main

# 2. Backup database (IMPORTANT!)
cp production.db production.db.backup

# 3. Check current version
alembic current

# 4. Show pending migrations
alembic history --verbose

# 5. Apply migrations
alembic upgrade head

# 6. Verify
alembic current
python -c "from database import get_database; print(get_database().health_check())"

# 7. Restart application
systemctl restart xboq-backend
```

## ⚠️ Common Scenarios

### Adding a NOT NULL Column

**Problem:** Can't add NOT NULL column to table with existing data.

**Solution:** Two-step migration:

**Migration 1:**
```python
def upgrade():
    # Add column as nullable first
    op.add_column('users', sa.Column('full_name', sa.String(length=255), nullable=True))
    
    # Populate with data
    op.execute("UPDATE users SET full_name = name WHERE full_name IS NULL")
```

**Migration 2:**
```python
def upgrade():
    # Now make it NOT NULL
    op.alter_column('users', 'full_name', nullable=False)
```

### Renaming a Column

```python
def upgrade():
    op.alter_column('users', 'old_name', new_column_name='new_name')

def downgrade():
    op.alter_column('users', 'new_name', new_column_name='old_name')
```

### Adding an Index

```python
def upgrade():
    op.create_index('ix_users_full_name', 'users', ['full_name'])

def downgrade():
    op.drop_index('ix_users_full_name', table_name='users')
```

### Data Migration

```python
from alembic import op
import sqlalchemy as sa
from sqlalchemy.sql import table, column

def upgrade():
    # Define temporary table structure
    users_table = table('users',
        column('id', sa.Integer),
        column('email', sa.String),
        column('username', sa.String)
    )
    
    # Migrate data
    op.execute(
        users_table.update()
        .where(users_table.c.username == None)
        .values(username=users_table.c.email.split('@')[0])
    )
```

## 🐛 Troubleshooting

### Issue: "Target database is not up to date"

```bash
# Check current version
alembic current

# Show history
alembic history

# Manually stamp to specific version
alembic stamp head
```

### Issue: Migration fails halfway

```bash
# Rollback
alembic downgrade -1

# Fix migration file
vim alembic/versions/XXXXX.py

# Try again
alembic upgrade head
```

### Issue: "Can't locate revision identified by 'XXXXX'"

```bash
# Reset alembic version
alembic stamp head

# Or start fresh (DESTRUCTIVE!)
rm xboq.db
alembic upgrade head
```

### Issue: Conflicts after git merge

```bash
# List migrations
ls alembic/versions/

# If you have multiple "head" migrations, merge them:
alembic merge -m "Merge heads" head1 head2

# Apply merged migration
alembic upgrade head
```

## 🔐 Best Practices

### DO ✅

1. **Always review autogenerated migrations**
   - Alembic can make mistakes
   - Check nullable constraints
   - Verify data migrations

2. **Test migrations up AND down**
   ```bash
   alembic upgrade head
   alembic downgrade -1
   alembic upgrade head
   ```

3. **Backup before production migrations**
   ```bash
   cp production.db production.db.$(date +%Y%m%d_%H%M%S)
   ```

4. **Use descriptive migration messages**
   ```bash
   # Good
   alembic revision -m "Add email verification to User model"
   
   # Bad
   alembic revision -m "changes"
   ```

5. **Keep migrations small and focused**
   - One logical change per migration
   - Easier to debug and rollback

### DON'T ❌

1. **Don't edit applied migrations**
   - Once deployed, migrations are immutable
   - Create a new migration instead

2. **Don't delete migration files**
   - History is important
   - Use `alembic downgrade` instead

3. **Don't skip testing**
   - Always run `test_database.py`
   - Test with real data

4. **Don't use autogenerate blindly**
   - Review every generated migration
   - Add data migrations manually

5. **Don't forget to commit migration files**
   ```bash
   git add alembic/versions/*.py
   git commit -m "Add migration: description"
   ```

### Manual Testing

```bash
# 1. Start fresh

python -c "
from database import get_database
db = get_database()
user = db.create_user(email='test@example.com', name='Test')
project = db.create_project(user.id, 'estimate', 'Test Project')
print(f'Created: User {user.id}, Project {project.id}')
"

# 3. Downgrade
alembic downgrade -1

# 4. Verify data lost (expected)
python -c "
from database import get_database
db = get_database()
try:
    user = db.get_user(1)
    print('❌ Data should be gone')
except:
    print('✅ Data correctly removed')
"

# 5. Upgrade again
alembic upgrade head
```

## 🆘 Getting Help

If you encounter issues:

1. **Check logs**
   ```bash
   alembic upgrade head --sql > migration.sql
   cat migration.sql
   ```

2. **Consult this guide**
   - Check "Common Scenarios"
   - Check "Troubleshooting"

3. **Test in development first**
   - Never test migrations in production first
   - Use a copy of production data

4. **Rollback if needed**
   ```bash
   alembic downgrade -1
   ```
